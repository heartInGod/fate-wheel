# 政策信号 Prompt（提取 + 报告）

本文件是 `policy_signals.json` 的录入规则，也是政策分析报告的生成模板。人工或 Agent 录入政策事件、写政策分析报告时，按此执行。打分与衰减由代码完成（`policy_signal.py`、`industry_heat.py`、`core_value.py`），这里只规定**如何把一份政策材料变成事件**，以及**报告长什么样**。

---

## Part A：政策事件提取 Prompt

你是政策信号提取员。输入是一份政策材料（发布会实录、政策文件、讲话、资金/项目公告）。输出是 `policy_signals.json` 里 `events` 数组的**一个**元素（JSON）。

### 1. 先判断要不要录

只录**国家级**材料：国务院、发改委、工信部、财政部、央行、证监会、国家数据局等部委，以及全国人大。地方文件、券商解读、媒体评论**不录**。
同一事件只录一次：媒体转载用原始出处，`url` 用官方页面。
没有新增内容的复述不录，例如“继续推进”“持续落实”而没有新目标或新措施的材料。

### 2. type（决定衰减速度，衰减由代码完成）

| type | 适用 | 半衰期 |
|---|---|---|
| `speech` | 领导讲话、表态、会议通稿中的一句话部署 | 5 天 |
| `presser` | 新闻发布会、政策吹风会、规划解读 | 7 天 |
| `regulation` | 监管规则、征求意见稿（含收紧类） | 15 天 |
| `document` | 正式印发的规划、行动方案、实施意见（有量化目标） | 20 天 |
| `funding` | 资金下达、项目清单、招标、专项债/特别国债额度落地 | 30 天 |

拿不准时选衰减更快的那一档。宁可让信号早点消失，也不要让旧政策长期加分。

### 3. industries：映射到东财二级行业，并给出强度 s

- 行业名**必须**是东财二级行业名，以 `cache/industry/heat_*.json` 的 `industries` 键为准，例如“半导体”“元件”“电网设备”“航海装备Ⅱ”“IT服务Ⅱ”。写完运行 `python3 main.py policy check` 校验。
- 强度 s（整数 −3..+3）：

| s | 判据（必须能在原文中找到对应句子） |
|---|---|
| +3 | 被点名为核心任务，**且**有量化目标、资金或专项工程 |
| +2 | 被点名为重点任务或重点方向，但没有量化目标 |
| +1 | 被提及，或属于直接上下游的间接受益 |
| −1 | 提及收紧、压减、“不过度”“防止一哄而上” |
| −2 | 明确限制新增、提高门槛 |
| −3 | 明确打压、清理整顿 |

- 只映射**直接**对应的行业。二级传导（比如“基建→钢铁→铁矿”）不录。
- 同一份材料里，一个行业只能有一个 s，取最强的那句。
- `why` 字段写原文要点加数字，不超过 40 字，例如“六大支柱之首，前三季度产量 +23.3%，首台套”。
- 判断是“加速”还是“收敛”时，要看与上一个五年或上一次表述的对比。新目标低于旧目标，即使措辞积极，也要按 0 或负值处理。例如“十五五”新建铁路 1.5 万公里低于“十四五”，铁路公路就不加分。

### 4. stocks（可选，慎用）

只在**公司主营业务与东财行业分类明显不一致、且政策直接点名该业务**时使用，例如东财归为“光伏设备”、但主业之一是储能逆变器（政策点名“新型储能”）的公司。s 最多 ±2，`why` 必须写明是哪项业务、对应哪条政策。不要因为“公司可能受益”就加分。

### 5. 输出格式

```json
{"id": "YYYYMMDD_来源_主题", "date": "YYYY-MM-DD", "type": "presser",
 "title": "…", "url": "官方链接", "local": "research/policy/xxx.txt（如有原文存档）",
 "industries": {"半导体": {"s": 3, "why": "…"}},
 "stocks": {"605117": {"s": 1, "why": "…"}}}
```

录入后依次运行 `python3 main.py policy check`，再运行 `python3 main.py policy` 查看衰减后的政策分。

## Part B：政策分析报告 Prompt

输入：
- `python3 main.py core review` 生成的 `logs/core/yyyyMMdd.md`，其中“政策信号”和“个股建议总表”两节由代码生成；
- `python3 main.py policy` 的输出；
- 政策原文存档 `research/policy/*.txt`。

输出：`research/policy/yyyyMMdd_政策信号报告.md`，按以下结构写：

1. **结论先行**（3–5 行）：本期政策的主基调（加速/收敛/监管），对持仓整体的影响，以及**是否需要操作**。
2. **有效政策事件表**：日期、类型、标题、当前衰减权重、预计失效日（权重低于 0.05 的那天）、来源链接。
3. **行业景气变化表**（只列政策分不为 0 的行业，以及持仓/自选涉及的行业）：基础分 → 政策分 → 最终分、分档、档位是否因政策改变、一句话原文依据。标出两类：
   - **共振**：政策分 > 0 且基础分 ≥ 60；
   - **左侧**：政策分 > 0 但基础分 < 50，或盈利门槛没过。只观察，不因政策买入。
4. **个股建议总表**（核心交付物，每只需要关注的股票一行）。范围：全部持仓（含 ETF），加上满足以下任一条件的自选股：系统分区为买入区、政策分不为 0、本次档位或分区有变化。

   | 代码 | 名称 | 身份（持仓-长线/持仓-交易/候选） | 行业 | 景气 基础→最终（政策分） | 档位（变化） | 现价 | 目标价 | 空间 | 分区 | 系统动作 | 政策要点 | 建议 |

   “建议”一栏的规则：
   - **以系统动作为准**。政策分只通过景气分和档位间接影响估值参数、买入线和空位排序，不能单独把“持有”改成“买入”。
   - 用以下词之一开头：**买入（首批 N 股）/ 补仓 N 股 / 持有 / 只做T / 卖一半 / 清仓 / 观察（左侧）/ 不碰**，后面加一句理由。
   - 档位因政策上调的标“（政策上调）”，并注明：“政策分会在 X 天后衰减一半，届时需由业绩验证”。
   - 成本约束（深套只做T、摊薄不足不加仓、低于保本价×1.05 不卖）优先于一切。
5. **待跟踪**：即将发生的政策事件（下一场发布会、文件印发、数据发布），以及需要人工复核的个股（例如行业分类与主业不一致）。
6. 末尾写：“以上为信息整理，不构成投资建议。”

格式要求：表格优先，每段不超过 3 句；所有数字都要能在输入文件里找到出处；不编造政策内容。
